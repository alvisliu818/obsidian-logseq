## 混合块(图片+代码围栏)编辑支持(深夜会话,commit 124d104)

用户报告:点击 `![图](...)\n```\ncode` 混合块,整块变成原始文本(图片语法可见)+ 页面跳动。根因是 `parseCodeFence` 只认纯围栏块,混合块走通用编辑器(840px 图片塌缩成一行文字)。

**方案——只换代码元素,不换整块**:
- `parseCodeFence` 接受任意行号的围栏 + `prefix` 字段(围栏前的行);围栏闭合后仍有非空内容 → null(数据安全护栏,防提交丢尾部)。
- 混合块聚焦:重新挂载**缓存的静态渲染**(contentCache WeakMap),只把其中的 `.lgp-code-block` 替换为专用代码编辑器(`replaceEl` 选项)——图片原 DOM 原位保留,布局几乎不变,**滚动位移实测 0**。
- 提交时把静态代码元素放回(`editingWrap.replaceWith(restoreEl)`),文本未变则缓存命中、零闪烁恢复;`parentElement` 判存(isConnected 在 detached holder 上会误判)。
- 混合块工具栏**总是**显示语言标签(lang 为空显示 "text")——它是进入 source mode 编辑前缀的唯一入口;source mode 光标位置要加 prefix 偏移。
- 光标定位:代码编辑器 doc 只含围栏内容,whole-text 坐标(staticPos/数字 pos)要减 `prefix + openLine` 偏移;点击坐标直接 posAtCoords(布局未变,映射准确),偏差 >60px 才回退 staticPos。
- `applyCursorAndScroll` 从 `{y:'center'}` 改 `{y:'nearest'}`(已在屏内则零滚动)——页面跳动的另一半根因。
- **stale editor 守卫**:渲染中途(滚动扩容/索引重建)重挂代码编辑器会泄漏旧 CM6 实例并把死 wrap 留在缓存 holder 里;挂载前 destroy + 还原。

验证:300 vitest(新增 6 个混合块解析测试)+ tsc + esbuild + e2e(混合块:图片保留/编辑器挂载/docLines=15 仅内容/滚动 0/光标在点击处/Esc 完整恢复/落盘结构完整;纯代码块回归:光标按比例映射 line 3/滚动 0/Esc 恢复)。已部署测试库与主库 BaiduSyncdisk。

## 混合块前缀可编辑(commit 76bc095)

用户反馈:点击混合块**代码上方的前缀文本**无法进入编辑。两个根因:(1) mountFocusedInto 的 codeInfo 分支劫持一切点击(含前缀)进代码编辑器;(2) 已聚焦时 focusBlockFromClick 的 focusedCode 分支只 refocus 代码编辑器。

**修复**:
- `prefixClick` 判定:`staticPos <= prefix.length`(staticPos 来自换前完整静态渲染,落在前缀内=点击在前缀区)→ 不挂代码编辑器,fall through 通用整文本编辑器,光标映射到点击行。
- focusedCode 分支:点击来自 holder(前缀)→ `commitFocusedText()`(还原静态代码元素,holder 完整)→ 继续走通用路径。代码编辑器在 holder **外**(replaceWith 换出),其内部点击永不冒泡到 holder——所以 holder 的 click 一定是前缀点击。
- **光标映射改"行号一致性"**:原 60px 偏差检查在塌缩场景失效——图片(841px)点击 Y 在塌缩后编辑器底部之外,posAtCoords 钳位到文档尾,而文档尾距点击 Y 仅 46px(<60)通过了检查。改为比较 posAtCoords 与 staticPos 的行号:不一致=布局塌缩,staticPos(换前真实点击行)为准;一致=posAtCoords 保留行内 x 精度。
